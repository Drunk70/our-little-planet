# 备份与换服务器

适用于当前的**本地媒体存储**：记录在 SQLite 数据库，照片、视频、语音和贴纸在 `data/media/`。

## 旧服务器到期前

1. 先保存正在编辑的内容。在作者后台打开「备份与迁移」，点击「下载完整备份」。只有登录作者才能下载。
2. 等待浏览器下载结束。生成与下载期间暂停新增、删除和修改，以免数据库快照和媒体文件对应不上。发生缺失或复制失败时会报错，不会把它当作成功备份。
3. 将 `.tar.gz` 文件留在自己的电脑上，最好再复制到移动硬盘。不要把唯一一份备份留在即将到期的服务器上。
4. 在已安装项目依赖的本地项目目录执行（路径带空格时加引号）：

   ```sh
   npm run backup:verify -- "/path/to/our-little-planet-backup.tar.gz"
   ```

   此命令在临时目录解包，逐个校验文件大小和 SHA-256、数据库完整性及媒体关联，不修改当前记录。

5. 同时保留项目代码版本（包括 UI 修改），单独保管 `.env.local`；这两项不在数据包内。Git/GitHub 只保存代码，不保存记录和照片。

也可以在旧服务器项目目录直接生成文件，用于手动下载或定时任务：

```sh
npm run backup -- "/path/to/backup-2026-11-08.tar.gz"
```

输出文件不能已存在，父目录需要事先创建。此功能不会自动安排定时任务，也不会自动上传到异地。

## 新服务器恢复

1. 安装 Node.js 22+、FFmpeg 和相同版本或兼容的新版本项目，安装依赖。**先不要启动网站、构建项目或运行 `seed`**，它们可能创建数据库或示例数据。
2. 上传备份包，在项目根目录执行：

   ```sh
   npm run restore -- "/path/to/our-little-planet-backup.tar.gz"
   ```

   工具会先在独立目录校验，再将完整数据放入 `data/`。目标目录必须不存在或为空。已有数据时直接拒绝，不提供静默覆盖选项；如新安装已自动创建 `data/`，先停止网站并将其移到别处保留。

3. 恢复或重新配置 `.env.local`：登录密码、随机签名密钥等；调整 Windows/Linux 不同的 FFmpeg 路径。当前备份恢复为本地存储，`OSS_*` 应留空，`NEXT_PUBLIC_DEMO_MODE` 应留空。
4. 构建并启动项目，登录后抽查手账、信件、照片、视频、实况、语音和设置。**不要运行 `npm run seed`**，那会清空现有数据。
5. 验证正常后，把域名解析到新服务器并配置 HTTPS；确认新站可用后才停用旧服务器。跨接入商迁移到中国大陆服务器时，还需按新接入商要求处理接入备案。

## 包含什么

- `journal.db`：数据库一致性快照，含未落入主数据库文件的 WAL 记录；包含记录、草稿、设置、彩蛋、涂鸦、评论、媒体关联等所有数据表。
- `media/`：本地媒体目录中的普通文件，包括缩略图和视频封面。
- `manifest.json`：格式版本、生成时间、应用版本、数量、文件大小与 SHA-256。
- `RESTORE.txt`：简要恢复说明。

不包含代码、环境变量、服务器/Nginx 配置及日志。数据包未经加密，其中包括私密内容和数据库里的彩蛋密码，应私人保管。文件校验用于发现传输损坏，并不能证明来源可信；只恢复自己保存的备份。

## 空间与运行限制

为保证失败时不会下载半成品，服务端先生成数据库快照、复制媒体并完成打包，再流式发送，避免把大视频全部装入内存。临时目录建议预留至少 **2 倍数据体积**的可用空间。正常完成、报错或断开下载后会清理临时文件；若进程被强行终止，系统临时目录中可能留下 `planet-backup-*` 文件夹，确认没有备份运行后可清理。

单个应用进程一次只允许一个后台备份任务。Nginx 的读取超时需要覆盖生成时间（例如该接口设置 `proxy_read_timeout 3600s;`），并关闭响应缓冲。照片、视频特别多时，可以停站后用命令行生成并传输备份。

目前一键备份**不支持 OSS**，检测到 OSS 配置或数据库中的远程对象路径会明确拒绝，防止得到只有文字、缺少媒体的“完整备份”。以后切换 OSS 前需要补充云端对象备份方案。

手动拷贝也可迁移，但必须先停止网站及所有写入进程，再复制整个 `data/`（包括存在的 `journal.db-wal`），不能在网站运行中只拷贝 `journal.db`。推荐使用上面的备份工具和恢复校验。
